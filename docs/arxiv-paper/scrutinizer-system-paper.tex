\begin{abstract}
Restricted Focus Viewers (RFVs) use mouse position as a gaze proxy to study visual attention on interactive content. Since the original RFV~\citep{blackwell2003}, through mouseview.js~\citep{anwylirvine2021}, every tool in this lineage has used Gaussian blur as its peripheral model---destroying spatial structure that real peripheral vision preserves. We present Scrutinizer, an open-source RFV that replaces Gaussian blur with a biologically-grounded peripheral pipeline, running on live web pages at 60\,fps. A GLSL shader implements four visual pathway stages using Difference-of-Gaussians band decomposition on the hardware MIP chain, enabling per-channel chromatic decay and content-aware saliency gating. The full pipeline preserves salient content up to 10$\times$ better than eccentricity-matched blur. Mouse-gaze alignment is a known limitation of all RFVs: cursor and eye diverge during reading and scanning~\citep{huang2012}. Scrutinizer inherits this constraint and does not claim gaze-level accuracy. Screenshot-based validation across five psychophysical domains characterizes where the pipeline matches published data and where GPU approximations introduce measurable error. Open source (MIT).
\end{abstract}

\section{Introduction}

The Restricted Focus Viewer (RFV) paradigm uses mouse position as a proxy for gaze, revealing content within a cursor-centered aperture while degrading the surround. \citet{blackwell2003} introduced the RFV to study visual attention without eye-tracking hardware; \citet{bednarik2007} validated it against eye-movement data, finding that mouse-contingent apertures produce fixation patterns consistent with gaze-contingent ones for spatial attention tasks. \citet{chetverikov2018} showed that mouse-contingent and gaze-contingent displays produce equivalent implicit processing effects in change blindness paradigms, providing direct evidence that cursor-directed apertures can substitute for eye tracking in attention research. The paradigm has been adopted in BubbleView~\citep{kim2017}, ViewSer~\citep{lagun2011}, ScreenMasker~\citep{orlov2016}, and most recently mouseview.js~\citep{anwylirvine2021}, which demonstrated reliable web-based attention tracking with cursor-directed apertures.

Every tool in this lineage uses Gaussian blur as its peripheral model. In 2006, \citet{queen2006} showed that desktop icons with distinct low-spatial-frequency silhouettes are identified ${\sim}$0.5\,s faster---but performing that analysis requires spatial frequency filtering most designers lack access to. The problem is general: Gaussian blur uniformly destroys spatial structure---layout cues, color contrasts, salient landmarks---that real peripheral vision preserves~\citep{rosenholtz2012}. Peripheral vision loses resolution, not structure; a designer testing information hierarchy with these tools sees uniform fog instead of selective, structure-preserving degradation. The peripheral model, not the mouse proxy, is the weak link.

Vision science offers a richer account of peripheral processing: cortical magnification~\citep{rovamo1979}, crowding~\citep{pelli2008,bouma1970}, differential chromatic decay~\citep{mullen2002}, texture statistics pooling~\citep{freeman2011,rosenholtz2012}, and saliency-driven gating~\citep{mcalonan2008}. Translating these into a real-time tool is an engineering problem: full texture synthesis~\citep{portilla2000} takes seconds per frame, and the most faithful real-time approaches~\citep{walton2021} require CUDA/DirectX compute not available in browsers.

Scrutinizer upgrades the peripheral model while staying in the RFV paradigm. An earlier prototype~\citep{edmonds2007} demonstrated mouse-contingent blur on live web pages using Adobe AIR (2007); instrumented browsers have logged mouse and navigation events for usability research since Uzilla~\citep{edmonds2003}. The current system implements four visual pathway stages in a GLSL fragment shader, with a WebGPU compute path for texture synthesis, running at 60\,fps. It contributes:

\textbf{(1)}~A DoG band decomposition on the GPU MIP chain providing individually addressable frequency bands for chromatic attenuation and saliency gating, at near-zero cost (13 \texttt{textureLod} calls).
\textbf{(2)}~A WebGPU compute path synthesizing oriented noise that preserves per-tile luminance statistics~\citep{freeman2011}.
\textbf{(3)}~Isotropic cortical sampling tiling the visual field into locally-square pooling regions derived from FOVI's cortical magnification function~\citep{blauch2026}.
\textbf{(4)}~A DOM structure extractor harvesting web accessibility annotations as top-down saliency priors.
\textbf{(5)}~A modular architecture with five branch points where researchers swap implementations without modifying the core shader.
\textbf{(6)}~Validation across five psychophysical domains (Section~\ref{sec:validation}), characterizing where the pipeline matches published data and where GPU approximations introduce measurable error.

\textbf{Mouse-gaze alignment.} The mouse proxy is a known limitation of all RFVs, but recent work reframes it as a complementary signal rather than a poor substitute. \citet{chen2001} found that mouse position correlates with gaze during web browsing; \citet{huang2012} showed that cursor and gaze diverge during reading and scanning. Critically, this divergence carries cognitive signal: \citet{stone2023} demonstrated that eye-mouse coordination breakdown reveals UX friction points that neither signal detects alone, and \citet{zhu2023} showed that cross-attention fusion of gaze and mouse improves activity classification by 7.4\% over either signal independently. Scrutinizer currently uses mouse position only. It is suitable for spatial attention tasks and design evaluation but not for reading research or saccade-level analysis. Eye-tracker integration via the gaze-input branch point is architecturally supported; combining both streams would access the coordination signal these studies characterize.

\textbf{Other limitations.} Eccentricity is computed in pixel units; without per-user viewing distance and display DPI calibration, the mapping to degrees of visual angle is approximate. The foveal radius (default 90\,px) is configurable for research use but requires expert calibration of viewing geometry.

\section{Architecture}

The default pipeline combines a fragment shader (${\sim}$1200~LOC, GLSL~ES~3.0) with 47 uniforms organized into biological stages, and---as of v2.3---two WebGPU compute passes (${\sim}$580~LOC, WGSL) that synthesize oriented noise preserving luminance variance in the periphery (Table~\ref{tab:architecture}). On hardware without WebGPU, the system falls back to MIP-only blur.

\textbf{Tradeoff scope.} The real-time constraint forces specific compromises: displacement instead of summary-statistic pooling, hardware MIP instead of continuous receptive fields, box-filtered frequency bands instead of Gaussian convolution. These are architectural constraints, not parameter choices---they define the boundary between what Scrutinizer can model at 60\,fps and what requires offline computation.

The architecture exposes five branch points (gaze input, saliency, crowding model, clutter scoring, and structure extraction) where researchers substitute implementations without modifying the core shader. A declarative mode registry (\texttt{modes.json}) defines 11 pipeline configurations as JSON objects, enabling zero-code A/B comparisons between pipeline variants. One switchable mode adapts FOVI's cortical magnification curve~\citep{blauch2026} ($M(r) = 1/(r+a)$, $a{=}2.78^{\circ}$) to MIP levels via $\mathit{mipLevel}(r) = \log_2(1 + r/a)$. At matched eccentricities, Scrutinizer's effective cutoff falls 3.5--4.6$\times$ lower than this CMF adaptation alone (measured by comparing $E_2$-derived band cutoffs against FOVI's CMF at 5$^{\circ}$, 10$^{\circ}$, and 15$^{\circ}$). The difference reflects scope: FOVI is an input transform designed for DNNs that learn downstream representations; Scrutinizer explicitly models the additional degradation from crowding, contrast sensitivity loss, and chromatic attenuation.

\subsection{DoG Band Decomposition}

Retinal ganglion cells have center-surround receptive fields modeled as DoG filters~\citep{kuffler1953}, with field size growing with eccentricity (M-scaling). The GPU MIP chain is a low-pass filter with power-of-2 resolution steps---a blunt instrument, but one that runs at hardware speed. We decompose it into an \emph{approximate} Laplacian pyramid by subtracting adjacent levels. Hardware mipmaps use box/bilinear filtering rather than Gaussian convolution~\citep{burt1983}, so band differences are Difference-of-Boxes rather than true DoG, with spectral leakage between bands. This is a deliberate tradeoff: the MIP chain was not designed to model the retina---it was built for texture filtering. They converge on the same structure because progressive spatial pooling is a good solution to the same problem:
\vspace{-2pt}
\begin{equation}
\text{band}_k = \text{textureLod}(\mathit{tex}, \mathit{uv}, k/2) - \text{textureLod}(\mathit{tex}, \mathit{uv}, (k{+}1)/2)
\end{equation}
\vspace{-4pt}

Twelve half-octave bands ($\sqrt{2}$ frequency spacing) span 5.66\,cpd (serifs) to 0.088\,cpd (large-scale structure), each weighted by a smoothstep rolloff with cutoffs at $c_k = E_2 \times (2^{k/2} - 1)$ for $k = 1 \ldots 12$, approximating cortical magnification~\citep{rovamo1979}. The DC residual (mean luminance component) always passes through---even far-peripheral vision preserves mean luminance. The result turns that blunt instrument into graded frequency loss: serifs drop while panel layout survives. Cost: 13 \texttt{textureLod} calls (half-integer LODs use hardware trilinear interpolation) vs.\ 1.

\subsection{Chromatic Processing}

Peripheral color sensitivity decays at different rates for red-green vs.\ blue-yellow channels~\citep{mullen2002}. The DoG bands provide the frequency axis; castleCSF~\citep{ashraf2024} returns per-channel sensitivity at each frequency and eccentricity. Red-green is attenuated 4--5$\times$ more aggressively than blue-yellow, calibrated against suprathreshold measurements from~\citet{bowers2025}.

\subsection{Crowding and Density Gating}

Crowding---feature binding failure in clutter~\citep{pelli2008}---is approximated via simplex noise domain warping, gated by local element density from the DOM structure map. Dense content (text clusters, UI grids) receives full distortion; isolated elements are spared. The sigmoid parameters are engineering fits, not derived from psychophysical data.

\subsection{Saliency and Structure Priors}

The LGN gates what reaches cortex~\citep{sherman2002}. \citet{mcalonan2008} showed that spatial attention enhances LGN gain at attended locations. We model this as saliency gating via a Web Worker that fuses three channels into a GPU texture:

\textbf{Bottom-up:} Oklab opponent-channel DoG (color saliency) and face detection via face-api.js~\citep{faceapijs} (TinyFaceDetector, 190\,KB).

\textbf{Top-down:} A DOM structure extractor walks the live page's element tree, rendering bounding boxes of text runs, media elements, and interactive controls (including ARIA roles) into an RGBA mask. This provides what bottom-up saliency cannot: knowledge that a control is interactive.

High-saliency regions receive up to 70\% of rendering bandwidth. The saliency worker computes every 15th frame (${\sim}$250\,ms); the DOM scan defers to idle callbacks (300\,ms debounce). A Feature Congestion pipeline~\citep{rosenholtz2007} scores local clutter from Oklab color variance and Sobel edge density, achieving Spearman $\rho = 0.93$ rank-order agreement with the original MATLAB implementation ($N{=}7$ web pages scored at matched resolution). In congestion-gated mode, local clutter modulates peripheral pooling strength by $1.0$--$2.0\times$.

\subsection{WebGPU Compute Mongrel (v2.3)}

The DoG band decomposition attenuates spatial frequency content but destroys luminance variance---peripheral regions become uniformly gray. Real peripheral vision preserves summary statistics (mean, variance, orientation energy) within pooling regions that grow with eccentricity~\citep{freeman2011,rosenholtz2012}. v2.3 adds a two-pass WebGPU compute pipeline that synthesizes oriented noise matching these statistics:

\textbf{Pass~1} (statistics, ${\sim}$300~LOC WGSL): 8$\times$8 workgroups extract per-tile Oklab statistics via parallel reduction---$L$ mean and variance, $a/b$ tile means, 4-direction orientation energies, and CMF-derived MIP level. Output: 48-byte \texttt{TileStats} struct per tile.

\textbf{Pass~2} (synthesis, ${\sim}$280~LOC WGSL): Per output pixel, four sine-wave gratings weighted by the tile's orientation distribution are scaled by $\sigma_L \times 1.5$ and added to the tile mean. Chrominance uses tile means directly (peripheral vision pools color more aggressively than luminance). Output is composited with eccentricity-dependent alpha so the fovea passes through unmodified.

Cost: ${<}$0.3\,ms total on Apple M3 integrated GPU (half-resolution frame copy). A safety harness monitors frame timing over a 60-frame rolling window; 10 consecutive frames exceeding 33\,ms trigger fallback to MIP-only rendering. Temporal smoothing (EMA, blend factor 0.3) stabilizes variance and orientation energy across frames while passing means instantly to avoid color lag.

This implements Tier~2.5 of the mongrel texture specification: statistical pooling via compute shaders, below the cost of full Portilla-Simoncelli synthesis (Tier~3) but above MIP blur (Tier~1). Section~\ref{sec:validation} validates that the compute path preserves measurably more luminance variance than MIP blur at matched eccentricities (H5/H6).

\subsection{Isotropic Cortical Sampling (v2.6)}\label{sec:isotropic}

A standard log-polar grid~\citep{schwartz1980} uses cortical magnification for ring spacing but keeps a fixed number of angular samples, so cells stretch tangentially at high eccentricities---aspect ratios exceeding 4:1 in the outer field. This creates a directional bias that does not exist in cortical representation: V1 neurons tile the visual field with roughly equal cortical area per receptive field, so angular and radial resolution degrade together, not at different rates.

v2.6 replaces the fixed tile grid with sector geometry derived from FOVI's cortical magnification function~\citep{blauch2026}. Ring boundaries are placed at uniform intervals in cortical distance:
\vspace{-2pt}
\begin{equation}
w(r) = \log(r + a), \quad a = 2.78^{\circ}
\end{equation}
\vspace{-4pt}

\noindent where $r$ is eccentricity in degrees and $a$ is the foveal scaling constant from~\citet{blauch2026}. Successive ring boundaries $r_i$ satisfy $w(r_{i+1}) - w(r_i) = \Delta w$ for a fixed cortical step $\Delta w$, so ring width $\Delta r$ grows with eccentricity. The spoke count per ring is chosen for local isotropy:
\vspace{-2pt}
\begin{equation}
n_\theta = \lfloor 2\pi r / \Delta r \rfloor
\end{equation}
\vspace{-4pt}

\noindent producing sectors that are approximately square in cortical coordinates (Figure~\ref{fig:fovi-geometry}). This replaces the fixed polar grid where outer cells stretched into arcs with aspect ratios exceeding 4:1. The sector extent at each eccentricity parameterizes both the Bender noise frequency (crowding distortion wavelength scales with sector width) and the Cutter cell size (texture synthesis pooling region matches cortical pooling).

\subsection{Jacobian-Corrected LOD Selection}

The GPU selects MIP level from screen-space derivatives of the texture coordinate---the Jacobian, a $2{\times}2$ matrix describing how the texture coordinate changes per pixel in $x$ and $y$. When V1 displacement warps the sampling UV, the original Jacobian becomes wrong: it describes the undistorted coordinate field, not the warped one. The hardware picks LOD from a Jacobian that does not match the actual sampling pattern---over-blurring radially (where the warp compresses UV) and under-blurring tangentially (where it stretches).

Passing \texttt{dFdx(distortedUV)} and \texttt{dFdy(distortedUV)} to \texttt{textureGrad} corrects this. The MIP tiles remain square---that is a hardware constraint. But level selection now tracks the warp, so the frequency content of the sampled texel matches what the displacement pipeline expects. This is the distinction between constraints to accept (tile shape) and constraints to work around (LOD selection).

A 19-test geometry validation suite confirms: ring boundaries match the FOVI Python reference implementation to 3 decimal places, spoke counts produce aspect ratios within 0.8--1.2 across all eccentricities, and total sector count scales logarithmically with field radius. OCR readability measured via Tesseract on filtered screenshots shows monotonically declining accuracy: fovea 84\%, parafovea 60\%, near periphery 62\%, far periphery 52\% (all 4 tier criteria pass). The non-monotonicity between parafovea and near periphery (60\% vs 62\%) is within OCR measurement noise (${\pm}5\%$).

\subsection{Known Limitations}

The pipeline matches published data where mechanisms map cleanly to GPU operations, and diverges where discrete MIP levels approximate continuous functions. The 12-band DoG produces step functions at MIP boundaries; Rovamo's smooth curves yield only $r = 0.600$. Crowding modulates distortion \emph{strength} by eccentricity, not \emph{spacing} by flanker distance~\citep{rosenholtz2012}. The saliency worker (256\,px) cannot resolve UI elements smaller than ${\sim}$60\,px; face detection (640\,px) provides the dominant protection signal. Two crowding calibrations were fit against test stimuli, making those results partially circular.

\section{Applications}

\textbf{Design audit.} The \texttt{scrutinizer-audit} CLI tool and MCP server provide batch Feature Congestion scoring without launching the Electron renderer, enabling CI integration. Designers see which elements survive peripheral vision before deployment. \citet{queen2006} showed that desktop icons with distinct low-spatial-frequency silhouettes are identified ${\sim}$0.5\,s faster in a match-to-sample task ($N{=}10$, 20 trial images), but this analysis requires spatial-frequency filtering that most designers lack access to.

\textbf{Research platform.} The five branch points and declarative mode registry make Scrutinizer a platform for perceptual experiments. Researchers can compare frequency-selective filtering against Gaussian blur on reading speed, swap in eye tracker SDKs or scanpath replay, or test how saliency models interact with crowding---all without modifying the core shader.

\textbf{Education.} Side-by-side comparison modes let users manipulate parameters and see results on their own content.

\textbf{Cognitive architecture integration.} The saliency branch point accepts any bitmap as attentional input, making Scrutinizer a rendering front-end for cognitive models such as SNIF-ACT~\citep{fu2007} and ACT-R's vision module~\citep{salvucci2001}.

\section{Open Problems}

\textbf{Full texture-statistics pooling.} The isotropic sector geometry (Section~\ref{sec:isotropic}) provides eccentricity-scaled pooling regions, but the compute path synthesizes oriented noise rather than full summary statistics~\citep{rosenholtz2012}. Covariance computation within isotropic sectors is feasible on WebGPU but not yet implemented.

\textbf{Gaze-cursor coordination as cognitive signal.} \citet{stone2023} and~\citet{zhu2023} show that the \emph{relationship} between gaze and cursor carries richer signal than either alone---coordination breakdown indicates friction~\citep{stone2023}, and cross-modal attention learns when to trust which input~\citep{zhu2023}. Integrating eye tracking via the gaze-input branch point would let Scrutinizer capture this coordination signal alongside the peripheral rendering, potentially connecting to information foraging models~\citep{pirolli1999} where gaze-cursor divergence may reflect scent evaluation.

\textbf{Experiment framework integration.} mouseview.js~\citep{anwylirvine2021} demonstrated that cursor-directed apertures integrate with jsPsych, PsychoJS, and Gorilla for web-based experiments. Scrutinizer's richer peripheral model could serve the same role, enabling researchers to compare biologically-grounded filtering against Gaussian blur within standard experiment frameworks.

% ============================================================
\section{Conclusion}

Scrutinizer is a Restricted Focus Viewer that replaces Gaussian blur with a biologically-grounded peripheral pipeline, running on live web content at 60\,fps. The DoG band decomposition provides per-channel chromatic attenuation and saliency-gated content protection (up to 10$\times$ advantage over matched Gaussian blur; Table~\ref{tab:gaussian_saliency}). The WebGPU compute path adds texture synthesis preserving peripheral luminance statistics~\citep{freeman2011}, and isotropic cortical sampling~\citep{blauch2026} provides biologically-scaled pooling regions. The mouse proxy inherits the limitations characterized by~\citet{chen2001} and~\citet{huang2012}; eye-tracker integration is architecturally supported. The branch-point architecture and open-source validation stimuli are designed so that other researchers can substitute tighter models---or plug the system into experiment frameworks alongside tools like mouseview.js~\citep{anwylirvine2021}.
