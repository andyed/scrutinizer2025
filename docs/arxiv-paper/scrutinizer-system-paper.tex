\begin{abstract}
Gaze-contingent tools used in HCI research---BubbleView, ViewSer, ScreenMasker---simulate peripheral vision with Gaussian blur, uniformly destroying the spatial structure that real peripheral vision preserves. They also operate on static images, not live interactive content. We present Scrutinizer, an open-source foveated rendering system that applies biologically-grounded peripheral filtering to live web pages at 60\,fps. A ${\sim}$1000-line GLSL shader implements a pipeline mapped to the visual pathway (retinal ganglion cells~$\rightarrow$ LGN~$\rightarrow$ V1~$\rightarrow$ V4), using Difference-of-Gaussians band decomposition on the hardware MIP chain for frequency-selective attenuation---high-frequency detail falls off first while low-frequency structure persists, approximating cortical magnification~\citep{rovamo1979}. The modular architecture maps each JavaScript module to a biological subsystem, enabling researchers to swap components independently (e.g., mouse gaze proxy~$\rightarrow$ eye tracker) and compare peripheral filtering strategies side-by-side---including a MIP-level adaptation of FOVI's cortical magnification curve~\citep{blauch2026} as a switchable mode. Open source (MIT), $>$130 unit tests.
\end{abstract}

\section{Introduction}

Peripheral vision is not blurry---it is \emph{differently encoded}. The retina compresses ${\sim}10^7$ photoreceptor signals into ${\sim}10^6$ optic nerve fibers~\citep{curcio1990}, with ganglion cell receptive fields growing with eccentricity~\citep{dacey1993}---effectively preserving low-frequency structure while filtering high-frequency detail. This is compute demand management: limited bandwidth allocated to information most likely to guide the next saccade.

Existing gaze-contingent tools---BubbleView~\citep{kim2017}, ViewSer~\citep{lagun2011}, ScreenMasker~\citep{orlov2016}---apply Gaussian blur as a peripheral proxy, uniformly destroying spatial structure and preventing layout-level judgments that real peripheral vision supports. These tools also operate on static images, not live interactive content (Table~\ref{tab:comparison}).\footnote{An earlier Scrutinizer prototype~\citep{edmonds2007} demonstrated mouse-contingent Gaussian blur on live web pages using Adobe AIR (2007), establishing real-time fidelity as the key technical challenge. Modern GPU APIs now make biologically-grounded filtering practical at 60\,fps.}

Scrutinizer contributes \textbf{(1)} a DoG band decomposition exploiting the GPU MIP chain for frequency-selective peripheral filtering at near-zero cost (5 \texttt{textureLod} calls), \textbf{(2)} a DOM structure extractor that harvests web accessibility annotations (ARIA roles, semantic HTML, computed styles) as top-down priors for the saliency pipeline---a computational analog of attentional modulation, without requiring a vision model, \textbf{(3)} a modular architecture (Table~\ref{tab:architecture}) with five branch points where researchers swap implementations without modifying the core shader, and \textbf{(4)} a side-by-side comparison with a MIP-level adaptation of FOVI's cortical magnification curve~\citep{blauch2026}: Scrutinizer's effective cutoff falls 3.5--4.6$\times$ lower at matched eccentricities, illustrating the combined effect of crowding, saliency gating, and color processing that FOVI delegates to downstream neural networks.

These contributions serve three use cases. \textbf{(a)~Vision research:} the branch-point architecture and parameter-controlled shader make Scrutinizer a platform for perceptual experiments---e.g., comparing frequency-selective filtering against Gaussian blur on reading speed and visual search (Section~\ref{sec:validation}). \textbf{(b)~HCI and usability:} instrumented browsers have logged mouse and navigation events for usability research since Uzilla~\citep{edmonds2003}; ViewSer~\citep{lagun2011} added restricted foveal viewing to study SERP examination at scale. Scrutinizer extends this lineage---the same cursor stream that drives interaction logging now also drives a biologically-grounded peripheral model on live content, letting researchers observe what users see, not just where they click. \textbf{(c)~Design evaluation:} \citet{queen2006} showed that icons with distinct low-spatial-frequency silhouettes are identified ${\sim}$0.5\,s faster---but this analysis requires spatial-frequency filtering that most designers lack access to. Scrutinizer provides it live: designers see which icons, buttons, and headings survive peripheral vision and which collapse into indistinguishable blobs, stress-testing information hierarchy before deployment.

\textbf{Limitations.} The current gaze input is mouse cursor position---a reasonable proxy when the user's eyes track the cursor, but unable to capture saccades, reading fixations, or gaze-cursor dissociation. Eccentricity is computed in pixel units; without per-user viewing distance and display DPI calibration, the mapping to degrees of visual angle is approximate. Perceptual validation against human peripheral discrimination thresholds is future work.

\subsection{DoG Band Decomposition}

Retinal ganglion cells have center-surround receptive fields modeled as DoG filters~\citep{kuffler1953}, with field size growing with eccentricity (M-scaling). We decompose the hardware MIP chain into an \emph{approximate} Laplacian pyramid---hardware mipmaps use box/bilinear filtering rather than Gaussian convolution~\citep{burt1983}, so band differences are Difference-of-Boxes rather than true DoG, with some spectral leakage between bands:
\vspace{-2pt}
\begin{equation}
\text{band}_k = \text{textureLod}(\mathit{tex}, \mathit{uv}, k) - \text{textureLod}(\mathit{tex}, \mathit{uv}, k{+}1)
\end{equation}
\vspace{-4pt}

Four bands span 1--2\,px (serifs) to 8--16\,px (buttons), each weighted by a smoothstep rolloff with cutoffs following a geometric progression ($0.3, 0.6, 1.2, 2.4 \times E_2$), approximating cortical magnification~\citep{rovamo1979}. The DC residual always passes through. Result: peripheral text shows letter shapes (low-frequency visible, identity unreadable) rather than uniform fog. Cost: 5 \texttt{textureLod} calls vs.\ 1, but near-zero practical overhead---higher MIP levels are cheaper, already cached, and arithmetic is trivial.

\subsection{Saliency-Driven Bandwidth Allocation}

The LGN's synaptic inputs are predominantly modulatory, with a substantial fraction from V1 feedback~\citep{sherman2002}; spatial attention enhances LGN gain~\citep{mcalonan2008}. We model this as saliency gating via a dedicated Web Worker that fuses three channels into a single GPU texture:

\textbf{Bottom-up:} Oklab opponent-channel DoG (color saliency) and face detection via face-api.js~\citep{faceapijs} (TinyFaceDetector, 190\,KB).

\textbf{Top-down:} A DOM structure extractor walks the live page's element tree, rendering bounding boxes of text runs (with computed font weight as density), media elements, and interactive controls---including ARIA roles (\texttt{role="button"}, \texttt{role="dialog"}, etc.)---into an RGBA mask. Two decades of web accessibility standards have produced a machine-readable semantic layer on most production websites; the extractor harvests this existing annotation as a free source of top-down priors. This provides what bottom-up saliency cannot: \emph{knowledge that a control is interactive}---a computational analog of the top-down attentional priors that modulate early visual processing. Because it reads the DOM directly, the extractor works on any web page without training data or a vision model.

High-saliency regions receive up to 70\% of rendering bandwidth. To keep the pipeline at 60\,fps, the shader renders every frame but expensive analyses run asynchronously at lower rates: the saliency worker (face detection + color DoG) computes every 15th frame (${\sim}$250\,ms); the DOM structure scan defers to idle callbacks on mutations (300\,ms) and yields the main thread entirely during form input (1.5\,s debounce). The GPU texture holding the combined saliency map persists between updates, so the shader always has a map even when the analyses are in flight.

\subsection{V1 Crowding and V4 Color}

Crowding is feature binding failure, not blur~\citep{pelli2008}. We approximate its visual effect via simplex noise domain warping and grid-based feature scrambling; this does not implement the summary statistic model of~\citet{rosenholtz2012} but produces qualitatively similar identity loss. V4 applies Oklab desaturation~\citep{ottosson2020} toward an eigengrau destination with a blue shift ($b{=}{-}0.05$ in Oklab), modeling the scotopic Purkinje effect---rod-dominated peripheral vision shifts sensitivity toward shorter wavelengths. This preserves blue-green into the periphery while red-green fades first, matching the direction of \citet{mullen2002}'s cone opponency data, though via destination modeling rather than differential channel decay rates. A lateral R/B channel offset simulates longitudinal chromatic aberration.

\subsection{Foveal Calibration}

The foveal radius---the boundary between high-fidelity central rendering and peripheral filtering---must match each user's actual foveal extent on their display. Without calibration, a 180\,px default subtends different visual angles on a 13'' laptop at 50\,cm versus a 27'' monitor at 70\,cm. We prototype a psychophysical staircase procedure using the Motion Silence Illusion: rotating crosses that appear static in peripheral vision due to crowding~\citep{pelli2008}. The staircase converges on the eccentricity at which users can no longer detect motion onset, with reaction-time weighting to penalize guesses. The result is a pixel radius stored per user. The current implementation does not convert pixels to degrees of visual angle---doing so requires viewing distance, which the Virtual Chinrest~\citep{li2020} estimates via blind-spot geometry ($\pm$3.25\,cm) and which EasyEyes tracks continuously via webcam face landmarks. Integrating either through the Gaze Input branch point would close the pixel-to-degree gap.

\subsection{Cortical Magnification: FOVI Comparison}

\citet{blauch2026} propose FOVI, a foveated interface for vision models built on a kNN-convolutional architecture over a retinal sensor manifold. FOVI's CMF is $M(r) = 1/(r+a)$, $a{=}2.78^{\circ}$; if resolution at eccentricity $r$ relative to the fovea is $a/(r{+}a)$, the number of halvings is $\mathit{mipLevel}(r) = \log_2(1 + r/a)$. The base-2 follows from MIP semantics (each level halves resolution); this is our adaptation, not FOVI's equation---FOVI builds a variable-density kNN sensor manifold, not a MIP chain. We do not implement FOVI's kNN sensor manifold, kernel mapping, or neural network pipeline---only the spatial resolution curve. At matched eccentricities, Scrutinizer's effective cutoff falls 3.5--4.6$\times$ lower than our CMF adaptation alone---the gap represents crowding, contrast sensitivity loss, and color processing that Scrutinizer bakes into its shader stages (V1 noise, saliency gating, Oklab desaturation) while FOVI delegates these to downstream learned representations.

A shared open question is the desaturation transfer function. Scrutinizer uses a smoothstep in Oklab fading toward eigengrau ($b{=}{-}0.05$), modeling the Purkinje effect; we also expose a Gaussian decay mode ($e^{-r/\sigma}$) for comparison. FOVI's \texttt{GaussianColorDecay} applies a single Gaussian ($\sigma$) uniformly across color channels toward gray. Both use a single decay rate, but \citet{mullen2002} show red-green (L-M) sensitivity declining $4{-}5\times$ faster than blue-yellow (S-(L+M)) with eccentricity---the 50\% crossover is ${\sim}$8--10$^{\circ}$ for L-M vs.\ ${\sim}$40--50$^{\circ}$ for S-(L+M), reflecting the architectural loss of midget ganglion cell opponency in the periphery while S-cone wiring persists retina-wide~\citep{calkins2001}. A dual-sigma model per opponent channel would capture this asymmetry with one additional parameter.

\section{Development Process}

The system was developed through iterative AI-human collaboration (Claude, Anthropic) where the agent served as \emph{research collaborator} maintaining biological grounding. Two examples illustrate complementary failure modes that the pairing catches:

\textbf{Agent catches cross-boundary bug.}
The saliency worker computed Oklab opponent channels on BGRA-ordered pixels from Electron's \texttt{capturePage()}. The agent traced the byte-order mismatch across 4 files and 3 processes (main $\rightarrow$ renderer $\rightarrow$ Worker)---a semantic error spanning process boundaries that human code review is unlikely to catch.

\textbf{Human catches conceptual drift.}
Documentation described ``degradation with preservation''---natural language for an engineering process focused on getting visual disruption correct. The human recognized this confused implementation with function: the retina's job is \emph{selective bandwidth allocation}, not degradation. The agent then swept 12 files (${\sim}$30 edits) to align language. The drift was invisible to the agent precisely because implementation-level accuracy \emph{had} been achieved; the conceptual error sat one level above the code.

The modular architecture enables both: the agent reasons per biological module rather than across a monolithic shader, and the human audits per biological claim rather than per file.

\section{Status \& Future Work}

\textbf{Implemented (v1.7.0):}
DoG band decomposition; saliency bandwidth allocation; noise crowding and grid scrambling; Oklab desaturation and chromatic aberration; foveal calibration; mobile emulation; FOVI CMF adaptation as switchable mode; $>$130 tests; golden capture regression. A declarative mode registry (\texttt{modes.json}) defines 9 pipeline configurations---6 research modes (High-Key, Biological/Purkinje, Frosted Glass, Log-Polar/FOVI, Legacy~v1.6, Gaussian Desaturation) and 3 presentation modes (Wireframe/Gestalt, Cyberpunk, Double Vision)---each specifying LGN gating, V1 distortion type, V4 style, and magnification model as a JSON object, enabling zero-code A/B comparisons between pipeline variants.

\textbf{Future:}
Dual-sigma color decay per opponent channel~\citep{mullen2002}; oriented DoG bands (oblique effect~\citep{appelle1972}); calibrated visual angles via Virtual Chinrest~\citep{li2020} or webcam distance tracking; webcam gaze integration~\citep{papoutsaki2016} as a consumer-hardware alternative to dedicated eye trackers. The V1 crowding stage currently uses noise-based appearance approximation; the branch point is designed so a Portilla-Simoncelli texture-statistics model---the same class that~\citet{walton2021} showed outperforms blur for foveated rendering---can be swapped in without modifying the rest of the pipeline. V2 (contour integration, border ownership) and V3 (global shape recognition) are not modeled---these require semantic representations beyond fragment-shader spatial filtering---but could be approximated via contour fragmentation and morphological simplification stages.

\textbf{Perceptual validation via restricted viewing.}\label{sec:validation}
Gaze-contingent restricted viewing---pioneered by \citet{mcconkie1975}---is inherently disruptive: with a one-word window, reading speed drops to 75--77\% of baseline; a three-word window matching the perceptual span recovers 98\%~\citep{rayner2010}. Gaussian blur exaggerates this cost because it destroys spatial structure that real peripheral vision preserves. \citet{walton2021} showed that texture-statistic metamers outperform bandwidth-equivalent blur for both task performance and artifact detection in foveated rendering. Scrutinizer's DoG bands preserve this kind of structure---low-frequency layout visible, high-frequency identity lost---but whether this translates to less task disruption than Gaussian blur at matched bandwidth is an empirical question. The validation experiment would compare task completion time, reading speed, and comprehension under Scrutinizer's DoG pipeline versus Gaussian blur versus unrestricted viewing. The open question is whether any gaze-contingent simulation can approach baseline performance, or whether inherent limitations impose a floor. Line-length reading is especially challenging: the perceptual span extends ${\sim}$15 characters rightward during natural reading, and the zoom-lens model of attention~\citep{eriksen1986} predicts that the attended region widens dynamically with task demands---a fixed-radius foveal window may need adaptive sizing or artificial accommodation for reading tasks. \citet{albert2019} found that fast readers are disproportionately affected by foveated rendering, making individual-difference measurement essential to any such study.

\textbf{Goal-directed attentional gating.}
The DOM structure extractor currently provides \emph{categorical} top-down priors (``this is a heading''). A richer model would encode \emph{user goals}: SNIF-ACT~\citep{fu2007} demonstrated that spreading activation between user goals and link text---``information scent''~\citep{pirolli1999}---predicts navigation behavior with remarkable accuracy. That work used PMI co-occurrence on a static corpus. Modern sentence embeddings (e.g., MiniLM, 384-dim, ${\sim}$23\,MB ONNX) make real-time cosine similarity between a goal vector and every DOM text node feasible in a Web Worker. The saliency branch point already accepts any bitmap; a ``scent map'' computed from $\cos(\vec{g}, \vec{c}_i)$ scores would close the loop from Pirolli and Card's information foraging theory to a live, gaze-contingent rendering pipeline---modeling not just \emph{what the eye can see} but \emph{what the mind is looking for}.
